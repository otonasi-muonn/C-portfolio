# ベストプラクティスガイド（C-portfolio）

`C-portfolio` で日常的に守る開発実践をまとめます。

---

## 1. 実装前

- `docs/DD.md` と `docs/_complete.md` を先に読む
- 変更範囲を最小化し、目的外の修正を入れない
- 文字列出力の安全性（`snprintf`, `html_escape`）を先に確認する

---

## 2. 実装中

- 既存の命名規則・責務分割（`data.c`, `render.c`, `main.c`）に従う
- 1機能1変更の粒度を意識し、レビューしやすい差分にする
- ドキュメントと実装がズレる変更は同時更新する

---

## 3. 実装後の確認

必須チェック:

```bash
make all
```

確認項目:

- ビルドが通る
- `dist/index.html` が更新される
- `dist/main.css` が正しく配置される

---

## 4. セキュリティ・品質

- `system`, `popen` のような危険な実行経路は追加しない
- ユーザー入力相当データは必ずエスケープする
- サイレント失敗を避け、エラーは明示的に扱う

---

## 5. ドキュメント運用

- 新しい運用ルールは `docs/Wiki/` に追記する
- README から辿れる状態を維持する
- 汎用テンプレート文言は残さず、このリポジトリ固有の説明にする
